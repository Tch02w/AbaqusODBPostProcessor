# Abaqus ODB PostProcessor

Abaqus 2025 ODB 批量后处理工具。当前工作树只保留唯一最新版代码；旧实现通过 Git 历史保存，不再使用 `*_v2.py`、`*_final.py` 等本地副本。

GitHub：<https://github.com/Tch02w/AbaqusODBPostProcessor>

## 本地目录职责

- 项目与源码：`G:\PythonProject\AbaqusODBPostProcessor`
- ODB：`G:\Job\GJA_ODB`
- 提取结果：`G:\Job\GJA_ODB\AbaqusODBPostProcessor_Results`
- 持久扫描/预扫描/数值缓存：所选 ODB 根目录下的 `cache`
- 当前会话批次临时目录：`%TEMP%\AbaqusODBPostProcessor\batches`
- 用户界面状态：`%APPDATA%\AbaqusODBPostProcessor\project_state.json`

项目目录中不存放 ODB、云图、CSV、GIF、XLSX、运行结果或扫描缓存。`.venv`、`.git`、源代码、测试、配置、文档与启动入口保留在项目中。

## 启动

- 双击 `Abaqus ODB 后处理器.lnk`；或
- 双击 `启动AbaqusODB后处理器.bat`。

双击 `打开源代码文件夹.bat` 可直接打开当前源码目录。

## 文件名规则

以 `GJA-1-R_U100D` 为例：

- `GJA`：A 方案钢筋混凝土模型；
- `1`：样本编号；
- `R`：配筋模型；
- `U100D`：上拔位移 100 mm，对应全局 3 方向；
- `V20D`：水平位移 20 mm，对应全局 1 方向；
- 同时存在 U、V：复合加载，读取 1+3 方向；
- `miu03/miu04`：变参数标签，不参与工况组名。

扫描后自动建立 `工况-U100D`、`工况-U40D_V20D` 等浏览分类。分类不是对比组，
不会参与组图例或组计算。主筋直径按样本编号自动匹配，并允许手动覆盖。

## 扫描、分组与并行

1. 点击“发现并选择 ODB”，第一阶段只枚举文件。
2. ODB 选择窗口分列显示文件名、大小、修改时间、兼容性和说明。
   文件名中的数字按自然顺序排列，例如 `GJA-2` 位于 `GJA-10` 之前。
3. 点击“检测所选 ODB”，或直接点击“开始读取”触发自动检测。
4. 检测结果区分：可直接读取、需要升级、版本高于本机、无效/损坏、空文件和文件不存在。
   稳定结果按 ODB 内容指纹和本机 Abaqus 版本写入 `cache\compatibility`；再次选择时只让
   Abaqus 检测新增或内容变化的 ODB。文件锁、许可证或进程异常等临时失败不会缓存。
5. 对 Abaqus 2021HF4 等旧版 ODB，点击“升级旧版 ODB 到 2025”后，新版继续
   使用原文件名，旧版改名为 `原名-old.odb` 保留；已有同名备份时自动递增编号。
   程序按全局并行数同时升级多个 ODB；每个任务先生成并验证临时新版，成功后才交换
   名称，失败时自动恢复原文件。取消升级只阻止尚未启动的任务，已经启动的升级会继续
   安全完成；等待期间不允许强制关闭升级窗口。
6. 升级成功后会再次以只读方式打开新 ODB，验证通过后才允许进入正式扫描。
7. 左侧“全部 ODB”和“按工况分类”只作为 ODB 来源；选中根节点或工况节点不会启动计算。
8. 右侧横向标签页对应用户创建的对比组。先打开目标标签，再从左侧将 ODB 拖入右侧
   表格即可添加成员；标签右键可新建、重命名、设置图例范围或删除组。标签可拖动
   排序，“全部配置”固定在最左侧；顺序按 ODB 根目录持久化，标签过多时使用左右
   滚动按钮，悬停可查看完整组名。“批量新建”提供默认 10 行的单列名称表，可粘贴
   任意行数并自动扩展；重复名称经确认后忽略。
9. 左侧 ODB 支持 `Ctrl` 离散多选、`Shift` 连续多选和一次拖放多个文件。双击单个
   ODB（或使用右键菜单）可切换为单项配置视图。
10. 只有单个 ODB 和用户创建的对比组可运行。提交后以“组”为单位进入当前会话的
    FIFO 队列，同一时刻只运行一个组；一个组入队后可继续提交其他组。“运行全部项目”
    按当前标签顺序追加尚未运行/排队的组，并将未加入用户对比组的已启用 ODB 作为
    单项运行，不改变已有队列顺序。等待项只保存组 ID、顺序和强制重扫标记；任务被
    提升为运行中时才冻结最新成员与配置。此时没有有效 ODB 或存在未识别方向会跳过
    该组并继续 FIFO。
11. 并行数范围 1–4，默认 2；它是全局设置，只控制当前运行组内部同时处理的 ODB，
    每个工作单元是独立 Abaqus 进程。
12. 组内 ODB 完成预扫描后统一确定图例上下限，再并行正式提取。
13. “取消当前组”只停止当前运行组，并在取消完成后继续下一个排队组；“取消全部排队”
    一键清空所有尚未开始的组，当前运行组不受影响。两者都不结束 `standard.exe`
    求解。退出时若仍有运行/排队任务，可选择返回，或取消全部并退出；程序等待其启动
    的 Abaqus 子进程结束后才退出。
14. 运行日志自动隐藏 Visual Studio Developer Command Prompt、`vcvars.bat` 和
    DPC++ 环境初始化噪声，保留许可证信息、ODB 错误、脚本异常和实际计算警告。

表格下拉框和数字输入框在关闭状态下会忽略鼠标滚轮，避免浏览表格时误改配置；
展开下拉列表后仍可正常滚动。界面使用 Qt 自带的 Fusion 浅色按钮、输入框、下拉框、
表格、滚动条和进度条，不再自绘控件；全局统一为 11pt 字号。ODB 树不显示所属
次数徽标；下拉列表关闭横向滚动条。

作业配置表不使用行选择或当前行高亮；点击只操作单元格内的复选框、下拉框和输入框，
不会再改变标题样式或在控件周围显示选中行底色。

荷载—位移等基础历程和所有 GIF 始终使用开始 Step 到结束 Step 的全部正式加载帧。
“帧模式”只限制 FreeBodyCut、纵筋数值提取等高开销计算；因此选择末帧不会再把
荷载—位移曲线截成一个点，也不会再生成只有末帧的普通动画。

“加载方向”显示为 `X方向、Z方向、XZ方向` 以及逐 ODB 的实际识别结果，例如
`自动（X方向）`、`自动（Z方向）`、`自动（XZ方向）`，内部对应 Abaqus 的
`1、3、1+3`。无法从文件名 U/V 工况识别时显示 `（未识别）`；必须手动选择方向后
才能提交，排队期间重新变为未识别则在激活时跳过该组。

标题栏显示软件名、版本和当前有效 ODB 根目录的完整绝对路径，便于同时打开多个工程。

默认自动复用缓存。“本次强制重新扫描”是一次性开关：扫描 ODB 时只重建本次所选
ODB 的基础缓存；运行当前组时重建该组预扫描缓存；运行全部时只影响本次新入队的组，
提交后立即自动复位，已经运行或排队的任务不受影响。缓存使用
`SHA-256(文件大小 + 头/中/尾固定采样)` 作为快速内容指纹，并将 mtime、Abaqus
版本、缓存 schema 和配置哈希分别记录。因此同内容 ODB 改名或复制后仍可复用。
升级成功时，程序会主动使旧指纹对应的兼容性、基础扫描、预扫描和数值缓存全部失效；
原文件名下的新版 ODB 会在下一次读取时创建新的基础缓存，避免采样指纹极端情况下
误用升级前的结果。

每个 ODB 的 GIF 图例按该 ODB 从开始 Step 到结束 Step 的全部动画帧统计一次，
并在整段动画中固定；不同 ODB 互不强制统一。静态云图仍按对比组统一图例范围。
同一内容指纹和数值提取配置快照命中时，后续对比组直接复用数值缓存，只按该组图例
重新渲染；日志会明确记录命中、未命中和复用。

每次后处理同时保留两套 PNG：`frames/`、`contours/` 是 Abaqus 直接输出且完全不
改写的原图；`frames_transparent/`、`contours_transparent/` 是去除近白背景后的
透明 PNG 副本。GIF 从未处理的完整帧生成，避免透明 GIF 调色板造成颜色或动画损失。

“输出图像”提供横向、纵向和单位设置。默认 `1500×1000 pixel`；pixel 模式按
输入比例创建当前屏幕可容纳的最大 Abaqus Viewport，再输出指定像素。切换为 mm
时，输入值直接作为 Viewport 的毫米尺寸并按屏幕原生像素输出。两种模式都不会再
使用固定的 180×120 mm 小 Viewport，因此图例、文字和模型保持正常比例。

主界面的“结果浏览器”按工程用途解释现有输出，不要求用户记忆内部目录和文件名。
左侧选择对比组、批次或 ODB；右侧结果框顶部使用“常用、数据、曲线图、云图、
动画、说明与日志、全部”横向标签，并可继续按荷载与位移、桩轴力、桩弯矩和
钢筋结果等具体内容筛选。带 `★` 的结果是推荐入口，默认优先显示；
支持图片/GIF/CSV/JSON 预览、直接打开文件、打开所在目录、复制路径和批量导出。
文件列表与预览区之间的分隔线可以上下拖动；图片和 GIF 始终保持原始宽高比缩放，
不会被预览区比例拉伸或裁切。CSV 和 XLSX 使用轻量表格预览：加载全部字段并提供
横向滚动，预览行数按文件大小自动控制，避免读取大型钢筋明细时卡住界面。
历史结果也可以直接读取，不需要重新提取。

正式提取会读取 ODB History Output 中 `KEY_1`、`KEY_2` 等根键接触反力和桩—土
接触摩阻，并与桩顶位移/反力逐帧对齐。`History_Output/contact_history_raw.csv`
保留 Abaqus 原始有符号力（N）；`History_Output/load_resistance_processed.csv`
提供统一为 kN 的桩顶反力、
逐根根键承载力、根键合力与平均值、桩侧摩阻、分担比例及力平衡余量。
`History_Output/load_resistance_notes.json` 记录符号约定和公式；平衡余量可能包含桩端阻力、
未提取分量及数值误差，不能未经核查直接当作桩端阻力。上述结果同时写入
`summary.xlsx` 的 `Load_Sharing` 和 `Contact_Raw` 工作表。
多层根键保留完整名称，例如 `KEY_1_1～KEY_2_4`，并分别给出单根结果和
`KEY_1`、`KEY_2` 组内合计/平均值。无法解析编号或变量类别时，只要 History Output
名称包含 `KEY`，仍按 Abaqus 原名称和值直接输出，不擅自换算单位或参加合力计算。

升级时 Abaqus 会在升级文件附近生成转换日志。应保留并检查该日志中的警告；如果
ODB 正在从超算下载或复制，应等待文件大小稳定后再检测。

## 结果结构

```text
G:\Job\GJA_ODB\AbaqusODBPostProcessor_Results\
├─ 用户对比组名\
│  └─ YYYYMMDD_HHMMSS\
│     └─ ODB名称\
├─ 未分组\
├─ _批次记录\
└─ _历史测试\
```

自定义对比组使用对应组名作为结果第一层目录。同一 ODB 属于多个组时，只提取一次
数值数据，其他组复用持久数值缓存并按各组图例重渲染。

## 当前代码结构

- `app.py`：两阶段选择和程序入口；
- `main_window.py`：基础表格与作业配置；
- `comparison_groups.py`：非嵌套、多成员对比组；
- `batch_window.py`：自动命名、并行批处理、取消与结果布局；
- `ui_style.py`：统一字体、控件尺寸、间距和高可读性样式；
- `paths.py`：缓存、状态与结果路径；
- `runner.py` / `process_runner.py` / `runner_parallel.py`：进程调度；
- `postprocess.py` / `postprocess_core.py`：宿主机后处理；
- `result_browser.py`：按工程用途查找、预览和导出已有结果；
- `abaqus_scripts/odb_compatibility.py`：ODB 有效性检测和旧版本升级；
- `abaqus_scripts/`：唯一当前 Abaqus 运行链；
- `tests/`：自动化测试。
